# validator-key-provisioning Specification

## Purpose
TBD - created by syncing change `wizard-deferred-keygen`. Defines how deferred validator identity and vote-account keypairs are generated on the host during provisioning, how start scripts fall back to the vote-account keypair file, and the explicit operator step for on-chain vote account creation.

## Requirements

### Requirement: Host generates deferred keypairs during provisioning
When the playbook runs with an empty `validator_identity_pubkey`, the node-base role SHALL (as today) generate `{{ secrets_path }}/funded-validator-keypair.json` if absent, then read its pubkey and `set_fact: validator_identity_pubkey` so later roles (alerting's watchtower `IDENTITY`) render the real value. When `vote_account_pubkey` is empty, the role SHALL generate `{{ secrets_path }}/vote-account-keypair.json` if absent (same `solana-keygen new -s --no-bip39-passphrase` pattern, `0600`-safe under the secrets dir) and `set_fact: vote_account_pubkey` from its pubkey. Supplied (non-empty) pubkeys SHALL never be overridden.

#### Scenario: Fresh host with both keys deferred
- **WHEN** the playbook provisions a host with both pubkey vars empty
- **THEN** both keypairs exist under the secrets dir afterwards, and the rendered watchtower unit and monitoring config contain the generated pubkeys, not empty strings

#### Scenario: Supplied pubkeys untouched
- **WHEN** the playbook runs with non-empty pubkey vars
- **THEN** no vote-account keypair is generated by this mechanism and both vars keep their supplied values in every rendered artifact

### Requirement: Start scripts fall back to the vote-account keypair file
The start-node templates SHALL emit `--vote-account {{ vote_account_pubkey }}` only when the var is non-empty, and otherwise `--vote-account {{ secrets_path }}/vote-account-keypair.json` — the file the deferred flow guarantees exists. An empty var SHALL never produce a bare `--vote-account` argument (the pre-change behavior with `""` was a broken command line).

#### Scenario: Deferred vote account start script
- **WHEN** the playbook renders a start script with `vote_account_pubkey` empty
- **THEN** the script's `--vote-account` argument points at the vote-account keypair file path

#### Scenario: Explicit vote account start script
- **WHEN** `vote_account_pubkey` is a pubkey
- **THEN** the script's `--vote-account` argument is that pubkey, byte-identical to pre-change output

### Requirement: On-chain vote account creation stays an explicit operator step
The wizard's next-steps output (when the vote account was deferred) SHALL print the exact on-chain creation command — `solana create-vote-account <vote-keypair> <identity-keypair> <withdrawer>` with the on-host secret paths filled in — and note that the validator cannot vote, and watchtower will alert, until it is executed with a funded identity. Nothing in the playbook or wizard SHALL submit on-chain transactions.

#### Scenario: Deferred flow prints the creation command
- **WHEN** the wizard completes with the vote account deferred
- **THEN** the next-steps output contains the `solana create-vote-account` command with the secrets-path file locations and the bootstrap-alerting caveat
